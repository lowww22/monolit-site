# Деплой сайта «Монолит» из России

Кратко: **Vercel из РФ часто недоступен** (оплата, регистрация, блокировки/деградация CDN). Для этого Next.js-сайта с формой `/api/contact` нужен **хостинг с Node.js**, а не чистый статический хостинг.

## Рекомендация

| Вариант | Сложность | API-форма | Кому подходит |
|--------|-----------|-----------|---------------|
| **1. Timeweb Cloud Apps (Dockerfile)** | Низкая | Да | Лучший выбор для новичка |
| **2. VPS Beget / Timeweb / Selectel** | Средняя | Да | Если нужен полный контроль |
| Статический хостинг (`output: 'export'`) | Низкая | **Нет** | Не рекомендуем — сломается форма |
| Cloudflare Pages / Netlify | — | — | Из РФ часто нестабильно / плохо оплачивается |

**Выберите вариант 1**, если хотите быстрее всего получить рабочий сайт с заявками в Telegram.

---

## Перед деплоем (один раз)

1. Залейте проект на **GitHub** (или GitLab / Bitbucket) — нужен аккаунт и репозиторий с этим кодом.
2. Подготовьте Telegram-бота для заявок:
   - напишите [@BotFather](https://t.me/BotFather) → `/newbot` → сохраните **токен**;
   - напишите боту любое сообщение;
   - узнайте свой `chat_id` (через [@userinfobot](https://t.me/userinfobot) или аналог).
3. Переменные окружения, которые нужно будет указать на хостинге:

```text
TELEGRAM_BOT_TOKEN=...токен от BotFather...
TELEGRAM_CHAT_ID=...ваш chat id...
```

В репозитории уже есть `Dockerfile` — он собирает сайт так, чтобы работали и страницы, и `/api/contact`.

## Вариант 1 — Timeweb Cloud Apps (рекомендуется)

Официальные материалы:

- [App Platform](https://timeweb.cloud/services/apps)
- [Деплой через Dockerfile](https://timeweb.cloud/docs/apps/deploying-with-dockerfile)
- [Next.js в Apps](https://timeweb.cloud/docs/apps/deploying-frontend-apps/nextjs)

### Шаги

1. Зарегистрируйтесь в [Timeweb Cloud](https://timeweb.cloud/my) (российский сервис, оплата картами РФ обычно проходит).
2. Откройте **App Platform** → **Создать** / **Добавить**.
3. Тип: вкладка **Dockerfile** (не «Frontend → static»).  
   Так надёжнее: у Timeweb для Next.js «из коробки» часто только static build, а нам нужен сервер ради формы.
4. Подключите GitHub/GitLab/Bitbucket и выберите репозиторий `monolit-site` (или как вы его назвали).
5. Ветка: обычно `main` или `master`. Автодеплой можно оставить включённым.
6. Регион: любой российский ДЦ Timeweb. Конфигурация: минимальная (сайту хватит небольшой машины).
7. Переменные окружения (`ENV` в панели):
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
8. Нажмите **Запустить деплой** и дождитесь зелёного статуса на вкладке «Деплой».
9. На **Дашборде** появится технический домен и HTTPS. Откройте сайт, отправьте тестовую заявку — сообщение должно прийти в Telegram.

### Свой домен (по желанию)

В панели приложения привяжите домен (например `beton-monolit.ru`) по инструкции Timeweb. SSL Let's Encrypt обычно выдаётся автоматически.

### Если деплой упал

- В логе ищите `npm` / `build` ошибки.
- Убедитесь, что в корне репозитория есть `Dockerfile` и `package-lock.json`.
- Переменные Telegram можно добавить и после первого успешного деплоя, затем перезапустить деплой.

## Вариант 2 — Дешёвый VPS (Beget / Timeweb / Selectel)

Подходит, если Apps неудобны или нужна своя машина.

1. Закажите VPS с Ubuntu (1 vCPU / 1–2 ГБ RAM достаточно).
2. Подключитесь по SSH.
3. Установите Node.js 22 LTS (через [NodeSource](https://github.com/nodesource/distributions) или `nvm`).
4. Клонируйте репозиторий:

```bash
git clone <URL-вашего-репозитория> monolit-site
cd monolit-site
npm ci
npm run build
```

5. Задайте переменные и запустите:

```bash
export TELEGRAM_BOT_TOKEN=...
export TELEGRAM_CHAT_ID=...
export PORT=3000
npm start
```

6. Для постоянной работы установите **PM2**:

```bash
npm i -g pm2
pm2 start npm --name monolit -- start
pm2 save
pm2 startup
```

7. Поставьте Nginx как reverse proxy на `localhost:3000` и получите бесплатный SSL через Certbot (или панель хостинга).

Beget: удобный российский хостинг/VPS, есть готовый образ Node.js в маркетплейсе — см. [раздел веб-приложений Beget](https://beget.com/ru/kb/how-to/web-apps).

## Почему не `output: 'export'` (Cloudflare Pages и т.п.)

В проекте есть серверный маршрут `app/api/contact/route.ts`: форма шлёт заявку на `/api/contact`, сервер пишет в Telegram.

При `output: 'export'` Next.js собирает **только статические файлы**. API-роуты **не работают**. Пришлось бы менять форму на `mailto:` / ссылку в Telegram — заявки станут неудобнее и менее надёжны.

**Вывод:** для «Монолита» оставляем Node-хостинг (Timeweb Apps Dockerfile или VPS). Статический экспорт — запасной путь только если сознательно откажетесь от серверной формы.

## Почему Vercel может не подойти из РФ

- Оплата зарубежными картами / санкционные ограничения платёжек.
- Регистрация и вход иногда блокируются или требуют обход.
- Даже при успешном деплое доступ к сайту из РФ может быть нестабильным (фильтрация зарубежных CDN/IP).

Для аудитории в Удмуртии надёжнее российский хостинг.
